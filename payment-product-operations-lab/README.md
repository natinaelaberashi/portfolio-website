# Payment Product Operations Lab

A practical portfolio project designed around the core workflow of a Payment Product Operations Specialist.

## Objective

Analyze synthetic payment transactions to identify operational patterns, investigate failures, monitor partner/product performance, and recommend process improvements.

## Workflow

1. Understand the operational question
2. Validate transaction data
3. Calculate core KPIs
4. Segment results by country, partner, product and status
5. Investigate failed/pending transactions
6. Identify recurring patterns
7. Prioritize operational issues by impact and SLA risk
8. Document findings and escalation evidence
9. Recommend preventive/process improvements
10. Monitor the next reporting period

## Tools demonstrated

- Excel: SUM, AVERAGE, COUNTIF, SUMIF, COUNTIFS, SUMIFS and PivotTables
- SQL: aggregation, filtering, grouping and operational exception analysis
- Dashboard: HTML/CSS/JavaScript operational KPI view
- Operations: SLA thinking, incident investigation, partner coordination and root-cause analysis

## Dataset

The project uses synthetic data only. It represents payment transactions with:

- Transaction ID
- Date
- Country
- Partner
- Product
- Currency
- Amount
- Status
- Processing time
- SLA target
- Error category

## Key questions

- What is total transaction value?
- What is the average transaction amount?
- How many transactions failed?
- Which countries and partners have the highest failed volume?
- What is the total failed value?
- Which transactions exceeded the SLA?
- Are failures concentrated around a specific product, partner or error category?
- Which operational issue should be investigated first based on volume, value and SLA impact?

## Interview connection

This project demonstrates the same thinking expected in payment product operations:

**Partners → Payments → Data → Investigation → Escalation → Resolution → Prevention**

It is intentionally built with synthetic data and is not connected to any production payment system.
